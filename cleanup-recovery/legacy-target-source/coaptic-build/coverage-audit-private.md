# Private Coaptic security-hardening audit

Source: library main 72c0083e8dd9cb2332e6cb91d1d4bfecffe2aa49 (timing branch does not change library code). Keep outside the public repository under SECURITY.md reporting policy.

1. Secret-bearing debug output: src/oscore/context.rs derives Debug for DeriveParams (master_secret/master_salt) and SecurityContext (sender_key/recipient_key/common_iv). Derived formatting exposes these fields. Replace with explicitly redacted Debug and add tests using known fixture secrets. This is a source-confirmed exposure path, not evidence that production secrets were logged.
2. Context lifecycle hardening: SecurityContext derives Clone, duplicating sender sequence/replay/binding state. set_sender_seq allows arbitrary replacement; derive resets sequence/replay state. Caller documentation requires persistence/advancement, but no durable checkpoint/replay restore API or crash-safe reservation example is present. Define safe restart and cloning contracts; prevent accidental nonce reuse. No secret zeroization/drop implementation was found. These are API/hardening concerns; copying a context is not by itself evidence of misuse.
3. Echo freshness: App challenge uses Echo::mint(now_ms, &[]); freshness only computes age from the supplied timestamp. age_ms uses saturating_sub, so future timestamps have age zero. No challenge equality/MAC validation is supplied by App. Do not treat this helper as independent authenticated freshness/address-validation proof. Qualify RFC 9175 protections and add bounded caller-provided challenge validation/entropy and negative tests. Existing secure-transport protection does not turn this standalone helper into an authenticated token validator.

Public issues #199-203 cover non-sensitive coverage/adapter gaps; #193 already tracks public legacy crypto advisories. These additional findings were not posted publicly.

Reconciliation at main f9b9793: #204 already redacts DeriveParams/SecurityContext Debug, removes SecurityContext Clone with a compile-fail proof, and refuses sender sequence rollback/overflow. #223 replaces implicit App Echo timestamp policy with an explicit caller issuer/verifier. These original audit findings are no longer outstanding in that form. Persistent replay/sender reservation recovery and zeroization boundaries still need qualification.

Reconciliation at main 6cce1f9: #235 adds validated replay checkpoints and monotonic live-context restoration, with authenticated replay/refusal and 256 modelled restarts. This is not crash-safe storage: callers own authenticity, freshness, context binding, commit-before-effects and sender reservations. App does not expose a pre-handler durable checkpoint barrier. Secret zeroization review remains open.

Fix in progress: explicit response PIV per Q payload; bounded recipient replay checks and binding lifetime through assembly. No public vulnerability issue/report created. Existing advanced protect_response remains caller-owned single-distinct-response semantics and needs explicit rustdoc.
