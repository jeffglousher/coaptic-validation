# Ordinary request-route permutation screen

This fresh experiment compares accepted core c655b3a with the exact candidate
bound in request_route_plan.json. Earlier parser and other rejected campaigns
stay stopped. The canonical JSON bytes, including the final LF, are the method
contract; native, runner, owner and receipts must bind its SHA-256.

Use the opt-in release bench-core --request-route qualify|measure GROUP MODE
protocol. This is a normal binary, not an ignored integration test. Four existing
wall tests and four new negative-test families run on each arm. Ten group/mode
qualification commands per arm run before timing; they report no timing arrays.
A separate proof-only run precedes the sole timing run, which rebuilds and
requalifies the exact timed executables.

Five setup groups cover SmallDevice route capacity four with one or four routes,
Default pools with eight routes, and Default pools with 32 routes both full and
sparse after removal/reuse. All routes have distinct response-body tags; a wrong
handler cannot pass merely by returning the same representation. Check every
response and actual handler delta, including authenticated 4.04 and 4.05 problem
bodies. Preserve one App/context pair, fresh process keys, unique MIDs/tokens and
fixed logical now_ms=1. No UDP or expiry transition is measured.

Cases interleave in a fixed round-robin trace. COMMON uses its own occurrence
counter to choose nine first hits then one last hit, continuously through warmup.
These are conditional mixed-trace estimates; cases share state and correlate.
They are not separate pure-traffic cohorts.

The 160 serial processes contain 8,000 measured polls, 128 warmups and 4,096
calibrations each. The complete raw census is 1,280,000 latencies, 20,480 warmups
and 655,360 calibrations. Four process pairs per order are the resampling units.
For each of 84 case/security/order comparisons enumerate all 256 ordered paired
index tuples, preserve every interval in its process mean and use the exact
weighted-linear one-sided .95 quantile in JSON. Eight designated unprotected
late/miss/shared-prefix decisions need point B/A <=0.97 and upper95 <1. Every
other decision needs upper95 <=1.02. All decisions are required. No pooling,
exclusion, calibration subtraction, replacement or post-data change.

Keep existing 830-second build, 300-second measurement, 30-second native process,
35-minute workflow, 8 GiB build and 64 MiB evidence limits. Aggregate refusal
controls despite 160 times 30 seconds exceeding 300 seconds. Failure preserves
completed prefixes and NOTRUN rows, not a smaller successful experiment.

Layout qualification precedes timing. Count N bytes of index backing
at every capacity (linear lookup above256), actual App layout and unchanged pool requests. Preserve core
owner ceilings; the new growth guard is explicit in JSON. The 193,536 bytes of
timing/calibration backing per process are additional fixture cost. App already
contains CoreIo and Site. Report headers, verification/context/static/scratch and
serializer owners separately. Emitted stack, futures, initialization and runtime
memory remain unknown; no whole-memory claim follows. The private retained
phase is preregistered at 16 MiB, separately from hosted evidence, before data.

Final candidate and suite source, tools, locks, flags, executable/PDB hashes,
process purpose/configuration, affinity and outer-owned restore/settlement must
be frozen and checked. This is conditional Windows release-binary App wall
comparison, not CPU, socket, device, host-independent or simultaneous-95% proof.
