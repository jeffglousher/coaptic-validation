Configuration, versions and measurement boundaries

  • The broad Coaptic fixture uses custom startup-sized AllocMemory with profiles::Default: one route, Calls 4, deferred 0, association 1, security bindings 4, Observe 4, dedup 8; RX4/TX4 × 1,472 B; one RX/two TX bodies sized to the representation rounded to 1,024 B. Blockwise is enabled; automatic growth is off. This is a different configuration from SmallDevice.
  • Bare Coaptic UdpSocket uses transient 1,473 B stack receive scratch. The reusable UdpSocketIo variant reserves 2,049 B scratch once. Neither number is total RAM. Pools and initialization precede the timed phase.
  • Coaptic spins one socket thread; coap-rs uses two Tokio workers; aiocoap uses asyncio; other runtimes keep their own defaults. This compares delivered fixture behavior, not equally tuned or native-client library speed. coap-lite is a codec endpoint, not a complete stack.
  • The native and matched aiocoap fixtures also differ in server transport/ETag setup. Cross-campaign changes cannot isolate Python driver cost. Within each displayed stratum the client and complete static-body workload are matched.
  • OSCORE is AES-CCM-16-64-128 / HKDF-SHA-256 with replay window 32 and fresh process-lifetime credentials. The shared sender context serializes sequence reservation and UDP dispatch. Setup, EDHOC, enrollment, durable counter/receipt commits and restart recovery are outside timing. Differences from unprotected controls include both client and server security, locking and GIL costs.
  • libcoap, coap-rs, go-coap and the codec fixture have no native OSCORE fixture in this harness. libcoap’s benchmark build disables OSCORE; this is a fixture limitation, not a claim that libcoap lacks it. DTLS is unmeasured. HTTP/3 TLS1.3 remains a separate protocol with warm/cold connections.
  • Closed-loop GETs use one outstanding request per endpoint, a 1-second deadline and no CoAP retransmissions. Measured latency includes complete byte verification. Endpoint rotation is included. Delivered goodput is completed payload bytes / measured wall time; this is not an offered-load capacity or corrected tail-latency study.
  • The full matrix records server-process CPU counters and host noise outside request timing. Windows CPU counters are quantized and include driver startup/warmup/exit in their window; they are not precise per-request CPU costs. Full-matrix process RSS/heap, whole-system memory peaks, initialization stack peaks and kernel socket buffers were not measured. SmallDevice layout and its sampled process RSS are separate overlapping views.
